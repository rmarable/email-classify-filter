## Context

A mailbox reaches `live` by passing the go-live test, tied to the **gate key**:
`claude_pins.pins()` (`src/ecf_server/claude_pins.py:121-136`) hashed by `key()` (:139). The key
holds each gate role's pinned model, the schema digest and the classifier's prompt digest
(`claude_review.prompt_digest`, :763), not the actor's instructions,
`src/ecf/data/plugin/agents/actor.md` (one template for `actor` and `actor_high`). A release
that edited only `actor.md` would change what ecf proposes while `live` mailboxes stayed `live`.
SPEC §1.2 (`SPEC.md:50`, P12) makes this due before the first release that edits `actor.md`;
v3.0.1 closes it now while nothing is `live` (accept has no addresses; testingecf is `assist`,
paused; checked 2026-10-16).

**Scope (operator decision 2026-10-16): `actor.md` only.** `classifier.md` has the same gap; it
is planned for v3.0.2, where it joins `claude_review.prompt_digest` as a fourth part (P2), so
v3.0.2 moves C's key only, not D's (D's classifier is Jev, `claude_pins.py:44-46`).

**Why a new field, not a part of `prompt_digest` (P15):** D's pins `prompt` is Jev's
(`claude_pins.py:132-133`), so D would miss actor changes, and `prompt_digest` is documented as
the classifier's.

**Effect:** the new field changes every C and D key once. At the first tick a `live` address
drops to `assist` (`stages.py:265-277`), its reviewed count restarts at 0 (`review.py:124`),
and the gate needs a fresh `/ecf-eval` (`gate.py:245-251`). Nothing is live, so the cost is nil.
Rollback to 3.0.0 drops a `live` address again, and so does re-upgrading (P12; `downgrade.py`
keeps 3.0.1's gate rows, whose `pinned_ids` 3.0.0 can't reproduce).

**Names (P1):** `actor_prompt` in the pins dict; `actor_prompt_digest` (full hex) everywhere
else. `actor_digest` is taken: old eval summaries use it for the retired local actor model
(`evalrun.py:822`).
