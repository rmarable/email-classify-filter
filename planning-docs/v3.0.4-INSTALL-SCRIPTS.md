# v3.0.4: install and uninstall scripts for macOS

Approved plan (operator, 2026-10-16), with the step 0 results and the decisions made after it (OD-526; SPEC §17.4 records what was built). Ships as v3.0.4 (operator decision 2026-10-16).

## Context
Installing ecf on a new Mac is manual (README.md:80-100, docs/admin-guide.md:28-60): install uv (and Python), install gh, download the release, compare SHA256 by eye, `uv tool install` the wheel, run `ecf init`. Removing it is `ecf destroy` per install, then `uv tool uninstall`, then guessing what's left. Operator request 2026-10-16 (state file Next steps 5): a bootstrap script and a matching uninstall script.

Decisions so far (operator, 2026-10-16): prerequisites come from their **official installers** by default, with an opt-in `--homebrew` route; scripts live in the repo **and** are attached to each release, listed in SHA256SUMS, with README telling people to download, read, then run (no `curl | sh`); uninstall **offers** to remove prerequisites, default no.

Not a classifier/rules/policy/facts/eval change, so no Phase R (CLAUDE.md "Adversarial review"). CHANGELOG line; released as v3.0.4 (operator decision 2026-10-16).

**Names** (operator 2026-10-16: names should say what they are): `install-ecf-macos.sh` and `uninstall-ecf-macos.sh`. They sit next to the wheel in a Downloads folder, so each names the program, the action and the platform; Linux versions (M5) would be `-linux.sh`. Tests: `tests/test_install_script.py`, `tests/test_uninstall_script.py`. The record file is `install-record.json`.

## Design
### `scripts/install-ecf-macos.sh` (POSIX sh, `set -eu`; runs with macOS's `/bin/sh`)
Steps, each saying what it does before doing it; `--yes` skips confirmations, `--version vX.Y.Z` picks a release (default: latest non-prerelease via the GitHub API), `--dry-run` prints the plan.
1. Checks: macOS, arm64 or x86_64, not root; FileVault on (`fdesetup status`; off → stop with how to turn it on, `--allow-no-filevault` to continue, mirroring `ecf init`'s "Continue anyway?"); screen lock (step 0 method; warn only).
2. Prerequisites, each skipped when a good-enough version is present: uv (official installer), gh (official `.pkg`, checksum verified against gh's checksums file), Claude Code (official installer; version ≥ 2.1.295). **`--homebrew`** (operator decision 2026-10-16; off by default): installs uv and gh with `brew install` instead; it never installs Homebrew itself (stops with a pointer to brew.sh when `brew` is missing); Claude Code still comes from its official installer unless step 0 finds an official Homebrew route. `install-record.json` records which route each tool came by, so the uninstaller uses the matching removal (`brew uninstall` or the official one). Python: bootstrap pins a tested version with `uv tool install --python 3.12` (uv downloads it if missing), never whatever newest Python uv finds.

**Python versions** (facts, 2026-10-16): `requires-python = ">=3.12.6"` (pyproject.toml:7) has no upper bound; the release and main CI test 3.12.6 and 3.13 on Linux (`release.yml:32`, `ci.yml:36`); the macOS gate runs 3.12 (`.python-version`: `>=3.12.6,<3.13`). So 3.13 is tested on Linux only and 3.14 not at all. The plan:
- Bootstrap installs with 3.12 (the macOS-tested one). `--python 3.13` allowed, with a line saying it's tested on Linux, not macOS.
- Docs (README "What you need", admin guide) say "Python 3.12 (3.12.6 or later) or 3.13" instead of "3.12.6 or newer"; the bootstrap note says it installs Python itself.
- `ecf doctor`'s `check_python` (`doctor.py:59`) warns on a Python newer than 3.13 ("not tested").
- Not in scope: capping `requires-python` at `<3.14` (it would block installs on a newer Python outright; a separate decision).
3. Download into a new temp dir (`mktemp -d`): the wheel, `SHA256SUMS`, `release-manifest.json`. Verify: the wheel's `shasum -a 256` equals its SHA256SUMS line; the manifest's tag and wheel hash agree with both. Any mismatch stops with nothing installed. States plainly that this proves the files match each other as published, not who published them (nothing is signed).
4. `uv tool install <wheel>`; if already installed, stop and point to `ecf upgrade` (never `--force` over a working install).
5. `ecf --version` check, then offer to run `ecf init` (default yes); without a terminal, print the command.
6. Records what it installed (uv, gh, Claude Code: installed / already there) to `~/Library/Application Support/ecf/install-record.json` for the uninstaller; never secrets.

### `scripts/uninstall-ecf-macos.sh`
1. Lists installs (`ecf` data root subdirs with a config; or `ecf` reports none). For each, explains, then runs `ecf destroy <install>` (interactive; step-up and typing the name stay ecf's), passing `--config-token` only if the person chooses to paste one (that's what deletes the Slack app).
2. When no install is left: `uv tool uninstall email-classify-filter`.
3. Lists what's left and what to do by hand: backup folder(s) (path from `destroyed/<install>.json` if it records it; else "your backup folder"), `.ecfcorpus` files, the `destroyed/` records, app passwords at each provider (Gmail: myaccount.google.com/apppasswords), the Slack app if not deleted, Claude login if logout failed. Offers to delete `destroyed/` and the empty data root (default no).
4. Prerequisites (from `install-record.json`, only those bootstrap installed; others named as "was already here"): asks about each, default no; uses each tool's own uninstall method (from step 0).
5. `--dry-run` shows everything without changing anything.

## Step 0 results (2026-10-16) and the decisions after them

1. uv: astral's `install.sh` (pinned form `https://astral.sh/uv/<v>/install.sh`) documents no checksum or signature (docs.astral.sh/uv/getting-started/installation, /reference/installer). The GitHub release publishes `uv-<arch>-apple-darwin.tar.gz` and `.sha256` (`<hex>  <name>`). uv downloads a managed Python automatically by default (docs.astral.sh/uv/concepts/python-versions); `uv tool install --python` picks the version.
2. gh: the `.pkg` is unsigned (cli/cli docs/install_macos.md) and needs sudo. The release has `gh_<v>_macOS_{arm64,amd64}.zip` (binary at `gh_<v>_macOS_<arch>/bin/gh`) and `gh_<v>_checksums.txt`. gh refuses every command without `gh auth login`, even `gh release view` on this public repo (tested 2026-10-16).
3. Claude Code: `curl -fsSL https://claude.ai/install.sh | bash`; launcher `~/.local/bin/claude` linked into `~/.local/share/claude/versions/`; binaries signed by "Anthropic PBC" and notarized (TeamIdentifier `Q6L2SF6YDW`, seen with `codesign -dvv` 2026-10-16); official Homebrew cask `claude-code` (code.claude.com/docs/en/setup, read 2026-10-16).
4. Screen lock: `sysadminctl -screenLock status` works without sudo on macOS 27 and prints `screenLock delay is immediate` on stderr.
5. Homebrew formulae `uv` and `gh`; cask `claude-code`.

Decisions (operator, 2026-10-16): uv and gh come from their vendors' release files checked against the published checksums, into `~/.local/bin` with no sudo (not `install.sh` or the `.pkg`); the installer offers `gh auth login` at the end (default yes); the release's wheel is kept in `<data root>/_installer/releases/<tag>/` because `ecf upgrade` needs the file `uv tool` recorded.
