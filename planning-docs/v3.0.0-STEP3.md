## 2. Ground rules (named before any run)

1. **Gates first, always:** 0 unsafe, fraud-guard recall 100% (literal, OD-460), no new miss on
   the injection cards. An arm or setting that fails a gate is out.
2. **One primary figure per arm** (P6), named here before R1; an arm is adopted only if its
   Newcombe paired 95% lower bound on that figure, against J0, is above 0 (or, for "no worse"
   figures, above −margin) and it passes rule 1. Secondary fields get McNemar with Holm, report
   only. Ties keep the default (s1, preamble in state, signals on, `fraud_risk` as `score`).

   | Arm | Primary figure |
   |---|---|
   | J1 s2 | injection-card misses (no worse) and `correct` (better) |
   | J2 preamble in instructions | injection-card misses, redaction on and off (§4) (better) |
   | J3 no signals | recall of each fixed item (no worse; §4 J3) |
   | J4 `fraud_risk` as choice | `fraud_risk` under-rated cases and unsafe (better) |
   | J5 reversed options | per-field agreement with J0 on hide-read fields (§4 J5) |
   | J6 `injection_attempt` | injection-card misses (§4 J6) |

3. **Fixed items are judged on recall** per run pairing, precision reported, accuracy report-only
   (P9; items are 92-97% negative). An item under 20 positives is report-only.
4. **Margin: 5 points, fixed** (P8, replacing S3-D2): never widened by either arm's noise; each
   arm's within-arm discordance is reported beside it.
5. **Noise:** J0 runs four times (P3); a difference inside J0's pairwise spread is not a
   difference.
6. **No tuning on gate cards** (schema doc §10, P9 there; PLANNING P18): settings are fitted by
   2-fold cross-fit (§6); the held-out batch is written after the freeze and its writer sees no
   results (§7).
7. **Every figure is labelled** cross-fit, in-sample or held-out (P9). A gate claim uses cross-fit
   and held-out only.
8. **Every result file kept** (`--copy-to state-archive/evals/`) until the decision using it is in
   SPEC (OD-486).
9. **S3-D9 (P21):** one operator go-ahead per batch (R1-R5), the batch's runs listed in it.

### 3.1 The unsure contract (P1)

- **P26 holds (step 4 P1):** a band may only add caution. The stored bool stays today's: yes at
  p ≥ 0.5 (`NOUL_TRUE`, `systemone.py:31`), so every reader sees at least today's answer. A
  band is a lower bound `lo` < 0.5 per banded field: **unsure** means `lo` ≤ p < 0.5. Above 0.5 is
  a yes exactly as today; no threshold is moved, up or down.
- `map_answers` keeps today's classification shape: every boolean a bool, validated by
  `schema.validate` (strict, `extra="forbid"`, `ecf/schema.py:343-352`). An unsure item is stored
  **`False`**, as today.
- `systemone.Answer` gains `unsure: frozenset[str]` (banded fields with `lo` ≤ p < 0.5) and
  `below_bar: frozenset[str]` (choice fields under their bar). Probabilities are kept as today.
- A reader that misses the unsure set behaves as today, never below it.
- The result file records both per case. D's source (`claude_eval._jev_run`, which copies the
  classification, `:321`) carries them too, so a D run sees the same holds.
- This is the contract step 4 builds on (§9).

### 3.2 The hold (P1, P10, P11)

One function, `evaljev.hold(plan, answer, rules)`, applied after `policy.plan` in **both** the live
eval scoring and the offline remap, so the two can't diverge:
- **Unsure item:** (1) rules read the stored field directly (`fixed_rules.yaml`, e.g.
  `phishing: {field: phishing, eq: true}`), so an unsure item fires no rule: no escalation or
  junk from a rule, as today; (2) the Python readers that test a fixed item or payment
  (`schema.fixed_item`, `policy.payment_or_fraud`, which reads `payment_related` directly,
  `policy.py:167-171`, and the others step 4 lists) treat it as **yes**: step-up and Approve-all
  exclusion, `batch_risky`, the alert lines, needs-own-review; (3) a **flag** is added to the
  planned actions, and the card (step 4) names the unsure item, since no rule labels it; (4) every
  hide on the case is **dropped** (the `policy.py:212-217` path: leave + flag), never kept as an
  approve-mode hide, `junk` included.
- **The eval simulates exactly this:** the plan is computed with the stored classification and
  with the unsure set passed to those readers (or, until step 4 builds that, by re-planning with
  the unsure items set true for the readers only, never for the rules); then (3) and (4).
- **Hide-read yes/no fields** (P11; `hide_fields`, `jev.py:1108-1119`; today `requires_action`,
  which `marketing` and `automated_notification` archive on when false, `starter_rules.yaml:50-62`):
  banded too, below 0.5 as every band. Unsure → treated as yes (the non-hiding value; also
  cautious in `actor.allowed`, which drops hide actions when it is true, `actor.py:47-48`) and any
  hide is dropped.
- **Choice field under its bar, read by a hide-capable rule** (`category`, `sender_type`): the
  label stays; any hide is dropped.
- **Readers** (step 4 P1's list; `_alert_echo` `policy.py:225`, `high_risk`, the approval mode,
  `precheck.py:78`, `answers.py:138`, `claude_queue.py:198`, `review.py:97-99`,
  `alert_items.py:140,146`): step 4 makes them see the unsure set. The eval covers the ones
  `policy.plan` and scoring call; any it can't reach is listed in §12.
- **New figures per run:** `held_for_person` (cases, by cause), unsure count per item, flags
  added, automation lost (cases whose correct outcome was a hide now dropped).
- With the shipped mapping equal to today's (0.5, no bands, no bars), `hold` changes nothing; a
  test proves it on the recorded fixtures.

### 3.3 The mapping as data (P16)

- `src/ecf_server/data/jev_mapping.json`: per-field band lower bound `lo` (< 0.5), per-field
  bar, the tie rule; the yes threshold is fixed at 0.5 and not in the file. Shipped equal to
  today (no band, no bar). A loader test refuses `lo` ≥ 0.5.
- `mapping_digest` hashes the **parsed canonical JSON** (`_sha`, `jev.py:1070-1072`), so
  formatting doesn't move the gate key; a test pins the shipped digest (as `PREAMBLE`'s SHA is
  pinned). The mapping commit moves `prompt_digest`, so `ecf eval compare` prints "different
  prompt" between J0 and later runs: expected, noted in SPEC §21.2.

### 3.4 One remap function (P15)

- `evaljev.remap(result, mapping, rules) -> cases`: rebuilds each case's classification, unsure
  and below-bar sets from stored `probabilities` under a candidate mapping, re-plans through
  `replan` (`evalrun.py:1450`) and applies `hold`. In process; writes nothing.
- The sweep script (§3.6) imports it (scripts may import `ecf_server`, `scripts/model_canary.py:26`).
  **No `--jev-mapping` CLI option or route** (draft 1's §3.2 is dropped): the committed mapping is
  checked by a fresh run (§7).
- A case whose stored answer didn't map (no probabilities) stays a failure under every mapping.

## 4. Stage 3b-1: noise, cold latency and arms

Every run: `ecf eval run --classifier-backend jev`, full 304-case set, redaction on, `--copy-to`.
Before R1, time one `null` run for the harness's share of wall time (P20).

| Batch | Runs | Purpose |
|---|---|---|
| R1 | J0 ×4 (defaults) | noise (pairwise discordance, per-field flips, per-card probability spread); the per-card mean probabilities for §6 |
| R1 cold | 20 single calls after ≥ 60 s idle and 10 after ≥ 10 min idle (the minimal key-check POST, no email content) | cold-connection latency (P7): the service's first call per check is always cold (fetch interval ≥ 5 min, `schedule.py:45-46`; keep-alive 60 s, `jev.py:78`) |
| R2 | J1, J2, J3, J4, J5, J6, two runs each; plus one `--fraud-only --no-redact` pair each for J0, J2 and J6 | the schema doc §11 list; the no-redact runs measure injections that trigger 10 would otherwise remove (P12), reported apart, never gate-counted |

- **J3 (R3, the pre-classifier for Jev):** answers "signals as a block" (P13). Each card's sent
  signals are recomputed offline (`Options.sent(facts)`) to report which fields move on the cards
  where each signal fires. A signal is dropped from Jev's state only if it fires on ≥ 20 cards and
  removing the block changes no safety field; otherwise it stays. A Jev-only subset of signals
  enters `state_format_id` (today it hashes all of `signals.WORDING`, `jev.py:1085-1092`).
- **J5:** a mitigation is considered if J5-vs-J0 agreement on a hide-read field is below the J0
  pairs' own agreement minus its 95% Wilson half-width.
- **J6:** kept only if, over two runs each, its fewest injection misses don't exceed J0's most
  (P6). If kept, it is a new fixed item for D: an OD, built in step 4.

**Cost and time:** TypeSafe about US$0.03-0.05 per full run; R1-R2 about 22 runs plus the cold
calls, under US$1.50. Wall time is stated after R1 from `wall_s` before R2 is scheduled.

## 6. Stage 3b-3: the fit, the settings commit and 3d

**Data:** the per-card mean probability over the frozen configuration's runs (J0 ×4 if the
defaults win; if an arm wins, two more runs of it, so it has four).

**Folds:** a deterministic assignment: cards sorted by ID within each pattern of banded-item and
fraud-guard positives, alternated between two folds; the fold list is printed and recorded. Each
card is scored under settings fitted on the other fold (cross-fit figures).

**Which items are fitted (P3):**
- `phishing` (93 positives): its own lower bound.
- `private_individual`, `bank_detail_change`, `claims_internal`, `regulator_claim`, and
  `payment_related` if it has fewer than 40 positives: **one shared lower bound**, fitted on
  their pooled cards; per-item bounds are not identifiable on this set, and SPEC says so.
- `requires_action` (hide-read, P11): its own lower bound, fitted on automation lost vs unsafe
  hides.

**Choosing each lower bound (operator decision 2026-10-14, 3a diff review D1; replaces the selection order):** a lower bound can only catch more true cards, so no fixed order of criteria picks one (the order drafted here always picked 0.30 or no band). `scripts/jev_sweep.py` prints, per group and candidate (`lo` 0.30 to 0.45 by 0.05, or no band), on every card and on each fold: unsafe cases, fraud-guard misses, true cards caught as unsure, true cards still a clear no, false cards flagged, held cases, automation lost, and the cards within 0.08 of `lo` and of 0.5. The operator chooses each bound from that table, as the bars.

**Confidence bars (P11; D4: `sender_type` under its bar holds every hide, since the hide blockers read it):** for `category` and `sender_type`, a table of automation lost and unsafe
hides per candidate bar (0.50-0.95). If no candidate changes an unsafe count, the bar is a design
margin: **the operator chooses** from the table.

**Settings commit (one commit, gate suite 0 skipped, CI):**
- `jev_mapping.json` gets the fitted values (fitted on all 304; the cross-fit figures are the
  honest estimate).
- **3d (P5):** the chosen state format, preamble placement, `fraud_risk` type and signal set become
  the only path; every losing switch value and its code (`state_s2` if s1 wins, the
  `questions(preamble=...)` branch not chosen, `--jev-option-order`, `--jev-extra-question` unless
  J6 is kept, `--no-signals` for Jev if not needed) and their tests are deleted. Result files keep
  the record.
- Then `accept` is restarted on `main` (P17) before R3.

## 11. Decisions

**Draft 1 (accepted as recommended, operator 2026-10-14):**
- **S3-D1:** 2-fold cross-fit on the 304 cards plus a fresh held-out batch (amended by P3: thin
  items share one band; folds by deterministic assignment).
- **S3-D2:** replaced by P8: a fixed 5-point margin.
- **S3-D3:** no over-size live test. ecf's estimate counts a UTF-8 byte as a token and refuses at
  30k/62k, about 9k/18k real tokens at the measured 3.4 bytes per token, far below Jev's 32k/64k.
  This rests on the assumption that Jev's tokenizer never gives more tokens than bytes (consistent
  with the 3.4-6.5 bytes per token measured; unverified, P21).

## 12. Limits stated with the results

- The set is Claude-written and public; whether Jev's training saw it is unknown.
- Jev's probabilities move by up to 0.08 between identical requests; cards near a band edge flip
  between runs (counted per item, §6).
- Four of the banded items share one lower bound; their per-item bounds aren't identifiable here.
- The settings are fitted on all 304 cards; cross-fit and the held-out batch are the honest
  estimates, and the held-out batch is too small to check a band.
- Readers outside `policy.plan` and scoring that step 4 makes see the unsure set aren't
  simulated by the eval (listed when 3a is built).
- A Jev run has no actor; D's actor is measured once (R5).
- Latency is from one machine and network over a day or two; cold latency from 30 calls.
- English-only cards except the 4 non-English `v3-*` cards; Jev states other languages are
  handled "not equally well".
