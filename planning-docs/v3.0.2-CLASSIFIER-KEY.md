## Context

Two items queued for v3.0.2 (operator decisions 2026-10-16; SPEC.md:52, SPEC.md:2542):

1. **`classifier.md` isn't in the gate key.** `claude_review.prompt_digest`
   (`src/ecf_server/claude_review.py:763-773`) hashes the schema fields, the signals' wording and
   the excerpt preparation, not the classifier agent's instructions
   (`src/ecf/data/plugin/agents/classifier.md`, shared by `ecf-classifier`, `ecf-classifier-high`
   and the eval classifiers). v3.0.1 closed the same gap for the actor (OD-523). Fix (SPEC §1.2
   `:52`): `classifier.md` joins `prompt_digest` as a fourth part, moving C's key only (D's pins
   take `prompt` from Jev's stored digest, `claude_pins.py:132-137`).
2. **A stale conversion notice.** Every upgrade from 3.0.0 reprints v3.0.0's "testingecf was
   preset A … now C and paused" (`cli_upgrade.py:264-270`), since `after_upgrade` copies the
   service's `converted` unconditionally (`upgrade_check.py:302-303`). Fix: print it only on the
   2.x→3.x crossing. **Doctor (operator decision):** keep its row until consent or removal, reworded.

**Effect:** the new `prompt_digest` changes every C key once (D's doesn't). A `live` C address
drops to `assist`, reviews restart, the gate needs a fresh `/ecf-eval`. Nothing is live today.
Existing C runs stay usable as frozen-run sources (`_claude_run` doesn't match on
`prompt_digest`, `claude_eval.py:399-444`) but compare as "different prompt" against later runs,
permanently (P12). `ecf reprocess` treats every C item as reclassifiable when run. The unpinned
eval key (`claude_eval.py:319-324`) doesn't hold `prompt_digest`, so comparison runs before and
after a `classifier.md` edit share a key; the summary records the difference (P10).
